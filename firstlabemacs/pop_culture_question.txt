## Artifact: *Dune* (Frank Herbert)

### 1. Imperative Paradigm → **House Harkonnen (especially Baron Vladimir Harkonnen)**

**Why it fits:**

* The imperative paradigm is about **explicit commands**, **step-by-step control**, and **mutable state**.
* The Baron operates exactly this way: issuing direct orders, micromanaging plans, adjusting tactics on the fly.

**Analogy details:**

* His plans are executed as sequences of commands: *do this → then this → if this fails, do that*.
* State constantly changes: alliances shift, troops move, power levels rise and fall.
* Control flow is explicit and centralized—everything traces back to the Baron’s instructions.

**Programming parallel:**

```text
1. Betray House Atreides
2. Install Rabban as governor
3. Increase spice production
4. If rebellion occurs, suppress it
```

This mirrors loops, conditionals, and assignments typical of imperative programming.

---

### 2. Object-Oriented Paradigm → **The Bene Gesserit**

**Why it fits:**

* OOP focuses on **encapsulation**, **abstraction**, **inheritance**, and **polymorphism**.
* The Bene Gesserit are all about carefully designed “objects” (people) with hidden internal state and well-defined interfaces.

**Analogy details:**

* Each Bene Gesserit sister is an “object” containing private data (memories, training, intentions).
* The **Voice** is a method: same interface, different behavior depending on the target (polymorphism).
* Genetic memory is inheritance—traits and abilities passed down across generations.
* Outsiders can’t see internal state; they only interact through controlled behaviors.

**Programming parallel:**

```text
class BeneGesserit:
    private memories
    private training
    public useVoice(target)
```

### 3. Functional Paradigm → **Paul Atreides (as Muad’Dib, prescient Paul)**

**Why it fits:**

* Functional programming emphasizes **immutability**, **pure functions**, **lack of side effects**, and **mapping inputs to outputs**.
* Paul’s prescience treats the universe like a mathematical function.

**Analogy details:**

* Given a specific input (a choice or event), Paul sees a deterministic output (future timelines).
* Futures are evaluated without “executing” them—similar to evaluating expressions without side effects.
* Paul increasingly avoids changing state directly; instead, he selects the path whose result he already knows.
* His struggle is that once a future is chosen, it becomes fixed—mirroring immutability.

**Programming parallel:**

```text
future = prescience(current_state)
chosen_path = min(jihad_outcomes(future))
```

---

### 4. Logic Paradigm → **Fremen Religion & Prophecy (Missionaria Protectiva)**

**Why it fits:**

* Logic programming is **declarative**: define facts and rules, then query the system.
* Fremen belief systems operate on rules and prophecy, not procedures.

**Analogy details:**

* Facts: “The Lisan al-Gaib will come from off-world.”
* Rules: “If a man fulfills the signs, then he is the Mahdi.”
* Paul doesn’t *prove* himself step-by-step; the Fremen **infer** his role by matching facts to prophecy.
* The Missionaria Protectiva preloaded the “knowledge base,” and reality resolves the queries.

**Programming parallel:**

```prolog
mahdi(X) :- off_worlder(X), desert_power(X), prophecy_signs(X).
```
